# SUGR Revival Website Specification

## Project

SUGR is the existing Sugar Bush meme token on Cardano.

This repository contains the official SUGR community website.

The original legacy website has been permanently archived in Git as
`legacy-v1.0.7`.

Development from August 23, 2026 onward represents a community-led
revival of the existing project, not the creation of a new token.

## Core Identity

Token: $SUGR

Blockchain: Cardano Mainnet

Official Policy ID:

`766fce8055f39d40fcfc19721677b3deb2e7846950ae08dce757f1e7`

Canonical Asset ID:

`766fce8055f39d40fcfc19721677b3deb2e7846950ae08dce757f1e753554741522042555348`

Historical claims must be accurate and verifiable.

Do not describe Charles Hoskinson as the creator of SUGR.
Do not claim that a SUGR cryptocurrency existed in 2013.
Do not claim that Sugar Bush was the first cryptocurrency meme coin.

## Revival Philosophy

The 2026 revival prioritizes:

- community
- transparency
- Cardano culture
- historical preservation
- low operating costs
- open infrastructure
- responsible stewardship of the existing project

The website should acknowledge SUGR's previous history rather than
pretending this is a new launch.

## Technical Requirements

The website must remain a static website.

Preferred technologies:

- HTML
- CSS
- vanilla JavaScript

Do not introduce without explicit approval:

- React
- Next.js
- databases
- server-side applications
- authentication systems
- npm dependencies
- external application frameworks
- paid infrastructure

The website must remain directly deployable through Cloudflare Pages.

Production deployment source:

GitHub repository:
SugarCardano/website

Production branch:
main

Development:
Use feature branches or dedicated development branches as required.
Changes should be reviewed before merging into `main`.

Legacy archive:
legacy-v1.0.7

## Infrastructure Principles

SUGR should not depend on:

- one developer
- one privately operated server
- the Sugar Factory
- the legacy SiteGround hosting
- a proprietary backend

The public website should be capable of operating with minimal ongoing infrastructure cost.

## Content Rules

Never invent:

- partnerships
- endorsements
- Charles Hoskinson statements
- Cardano news
- treasury information
- token statistics
- historical facts
- exchange listings
- development commitments

Unknown information must remain unknown until verified.

## Financial Content

Do not:

- promise financial returns
- make price predictions
- tell users to buy SUGR
- imply guaranteed appreciation
- present staking or yield opportunities that no longer exist

Trading information may be presented factually where verified.

## Legacy Services

Sugar Factory and Sugar Crash are legacy services.

They are not dependencies of the revived SUGR website.

Legacy services should not be presented as part of the current SUGR
product offering.

Where necessary, Sugar Factory may be referenced separately for legacy
user recovery or withdrawal purposes while such functionality remains
available.

Do not rebuild Sugar Factory as part of the website.

Do not rebuild Sugar Crash as part of the website.

Do not accept new staking deposits through the revival website.

## Security

Never commit:

- wallet seed phrases
- private keys
- signing keys
- wallet backup files
- Discord bot tokens
- API secrets
- GitHub tokens
- Cloudflare tokens
- passwords
- `.env` files containing credentials

Public blockchain information such as verified wallet addresses,
transaction hashes, native scripts, script hashes and public key hashes
may be documented for transparency.

Public blockchain information must not be confused with private signing
material.

## Design Direction

Preserve the playful Sugar Bush / squirrel personality.

The website should feel:

- fun
- mischievous
- historically interesting
- unmistakably Cardano
- community-driven

It should NOT feel like:

- a corporate fintech website
- a generic AI-generated crypto landing page
- a casino
- a high-yield investment platform

Existing legacy imagery and design assets may be reused where
appropriate, subject to confirmation of applicable usage rights.

## Primary Narrative

The strongest narrative is:

"The Meme Crypto Forgot."

The historical structure should broadly communicate:

Internet-era Sugar Bush
→ 2013 Bitcoin meme experiment
→ 2024 SUGR on Cardano
→ decline of the original project
→ 2026 community revival

The 2013 event should be presented accurately as an early attempt to use
internet meme culture to promote cryptocurrency.

## Website Priorities

The revived website should prioritize:

1. Story and historical context
2. SUGR identity and verification
3. Community revival
4. Transparency
5. Official community resources
6. Verified external trading and market references

Buying the token should not dominate the website.

## Development Principle

AI assists with implementation.

Project identity, historical claims, governance,
financial information and strategic direction are
determined by the human revival team.

AI must not independently redefine the project.

## Transparency

Transparency is a core principle of the revived project.

Public project records should identify and maintain:

- official treasury wallet
- verified treasury control policy
- major treasury transactions and expenditures where appropriate
- official GitHub repositories
- revival infrastructure
- community channels
- project history
- legacy service status

Treasury information may only be published after the relevant address,
native-script policy and supporting on-chain information have been
independently verified.

Private signing material must never be published.

## Historical IP and Attribution

The documented 2013 Bitcointalk story involving Charles Hoskinson and
Sugar Bush may be discussed as historical context for SUGR.

Historical references must be factual, attributed, and linked to primary
sources where possible.

The website must clearly distinguish:

- the 2013 Bitcoin promotional concept
- the creation of the SUGR Cardano token in 2024
- the community-led revival beginning on August 23, 2026

The website must not imply that:

- SUGR existed in 2013
- Charles Hoskinson created or endorsed the current SUGR token
- the revival team owns Sugar Bush intellectual property
- Kelly Foxton or any Sugar Bush rights holder endorses SUGR
- SUGR is the official cryptocurrency of Sugar Bush

Third-party names may be referenced where reasonably necessary to describe
documented history, but third-party photographs, logos, character artwork,
or other protected creative assets must not be used as the revived project's
core brand unless appropriate usage rights are confirmed.

The revived project's primary identity is SUGR, its Cardano history,
community revival, transparency, and open infrastructure.
